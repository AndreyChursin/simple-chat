# Чек-лист ручного тестирования

Проверка в браузере того, что уже реализовано (этапы 1–6). Автотесты (`pytest`, `vitest`) покрывают API и логику. Этот список — про то, что видит человек: интерфейс, живые обновления, несколько вкладок и браузеров. Дополняется на каждом этапе.

## Подготовка

1. `docker compose down -v && docker compose up --build`. Дождаться, пока http://localhost:8080 откроет страницу входа.
2. Понадобятся **три независимых браузера**: обычное окно, окно инкогнито и другой браузер. Cookie сессии общая на все вкладки одного профиля, поэтому два пользователя в одном профиле не уживутся.
3. Зарегистрировать `alice`, `bob`, `carol` через `/register` (пароль ≥ 8 символов) или через API:
   ```bash
   for u in alice bob carol; do
     curl -s -H "Origin: http://localhost:8080" -H "Content-Type: application/json" \
       http://localhost:8080/api/auth/register \
       -d "{\"email\":\"$u@example.com\",\"username\":\"$u\",\"password\":\"password123\"}" >/dev/null
   done
   ```
4. Письма (сброс пароля) смотреть в Mailpit: http://localhost:8025.

Обозначения: **A**, **B**, **C** — браузеры alice, bob, carol. «Сразу» значит ≤ 2–3 с без перезагрузки страницы.

---

## 1. Аккаунт и сессии

- [ ] Регистрация с уже занятым email или username (в другом регистре, например `ALICE`) → ошибка под соответствующим полем.
- [ ] Неверный пароль при входе → «Invalid e-mail or password» (без уточнения, что именно неверно).
- [ ] Вход **без** «Keep me signed in», затем закрыть браузер целиком и открыть снова → нужно войти заново.
- [ ] Вход **с** «Keep me signed in» → после перезапуска браузера сессия жива.
- [ ] Profile: username только для чтения, с подписью «Username cannot be changed»; display name сохраняется и виден в меню.
- [ ] Change password с неверным текущим паролем → ошибка. С верным → тост «Other sessions were signed out», другая сессия того же пользователя разлогинена.
- [ ] Forgot password → письмо в Mailpit → ссылка → новый пароль → вход с ним. Повторно открыть ту же ссылку → «Link expired or already used».
- [ ] Sessions: видны браузер/ОС/IP/время, текущая помечена «This device». «Sign out» на чужой строке → та вкладка **сразу** уходит на `/login`.
- [ ] Sign out в одном браузере не разлогинивает другой браузер того же пользователя. Все вкладки того же браузера уходят на `/login`.
- [ ] 6+ неудачных входов подряд → сообщение о rate limit.

## 2. Комнаты, каталог, приглашения

- [ ] Без открытого чата: в левой панели раскрыты все секции, правой панели нет.
- [ ] Create room: имя короче 3 символов → ошибка; имя занято (в любом регистре) → ошибка под полем. Успех → открывается новая комната.
- [ ] Внутри комнаты левая панель сворачивается до секции текущего чата; другие секции раскрываются вручную, и это запоминается. Справа — участники.
- [ ] Public Rooms: поиск по имени и описанию, число участников, кнопки Join / Open.
- [ ] **B** нажимает Join → попадает в комнату; у **A** число участников и список обновились сами.
- [ ] Приватная комната **A** не видна **C** в каталоге. Прямой URL `/rooms/<id>` у **C** → «Room not found».
- [ ] **A** приглашает **C** (Invite user, подсказки по username) → у **C** сразу тост и бейдж на «Private Rooms» → Accept → **C** в комнате.
- [ ] Повторное приглашение того же пользователя → «already has a pending invitation»; приглашение участника → ошибка.
- [ ] Manage room → Invitations: видны pending-приглашения, Revoke убирает приглашение у адресата.
- [ ] Владелец не может выйти (вместо кнопки подсказка). Участник: Leave room → возврат на главную, комната пропала из панели.
- [ ] Manage room → Settings: обычный участник/админ видит поля только для чтения. Владелец меняет имя/описание/видимость → у других участников обновилось.
- [ ] Удаление комнаты требует ввести её имя. После удаления у участников, которые были в ней, — переход на главную и тост «Room #… was deleted».

## 3. Сообщения

- [ ] Сообщение **A** появляется у **B** сразу, во всех его вкладках.
- [ ] Enter — отправка, Shift+Enter — перенос строки; многострочный текст сохраняет переносы.
- [ ] Emoji из кнопки 😊 вставляется в позицию курсора.
- [ ] Ссылка `https://…` кликабельна и открывается в новой вкладке. Текст `<b>x</b>` показывается как есть, без HTML.
- [ ] Длинный текст: после 2800 байт появляется счётчик; после 3072 он красный, Send заблокирован. Кириллица (2 байта) и emoji (4 байта) считаются в байтах.
- [ ] Reply: плашка «Replying to …» над полем, Esc отменяет. В ленте у ответа цитата; клик по цитате прокручивает к оригиналу и подсвечивает его.
- [ ] Edit своего сообщения (меню или ↑ в пустом поле) → у всех пометка «edited». У чужих сообщений Edit нет.
- [ ] Delete своего с подтверждением → у всех «Message deleted». Цитаты на него показывают «Original message deleted».
- [ ] Админ/владелец комнаты может удалить чужое сообщение. Обычный участник — нет.
- [ ] Набор текста у **B** → у **A** «bob is typing…»; исчезает после отправки или через ~5 с.
- [ ] История: в комнате с сотнями сообщений прокрутка вверх подгружает старые без скачков ленты, наверху — «Beginning of conversation».
- [ ] **A** читает историю (прокручено вверх), **B** пишет → лента **A** не дёргается, появляется «↓ 1 new message»; клик ведёт вниз.
- [ ] **A** внизу ленты, **B** пишет → лента **A** сама прокручивается к новому сообщению, оно видно целиком.
- [ ] Поиск 🔍: находит по подстроке; клик по результату переходит к сообщению, даже если оно далеко в истории.
- [ ] Отключить сеть у **A** (DevTools → Offline), **B** пишет, включить сеть → пропущенное появляется у **A** без перезагрузки.
- [ ] Отправка при выключенной сети: сообщение полупрозрачное («sending»), после возврата сети отправляется один раз, без дубля.
- [ ] Офлайн-пользователь при следующем входе видит всё, что было написано без него.

## 4. Присутствие (presence)

- [ ] **B** открывает приложение → у **A** точка **B** в участниках сразу ● (online).
- [ ] **B** не трогает мышь и клавиатуру > 1 минуты (во всех своих вкладках) → у **A** ◐ (AFK). Движение мыши у **B** → сразу ●.
- [ ] У **B** две вкладки: активность в любой одной держит ●.
- [ ] Перезагрузка страницы у **B** не даёт мигания ○ у **A**.
- [ ] **B** закрывает все вкладки → у **A** ○ (offline) примерно через секунду.
- [ ] Участники в правой панели пересортировываются: online → AFK → offline.

## 5. Контакты, баны, личные сообщения

- [ ] **A** → Contacts → Add friend → `bob` + приветствие → «Friend request sent». У **B** сразу тост и бейдж на «Contacts».
- [ ] **B** → Requests: видно приветствие → Accept → открывается DM с **A**. У **A** **B** появился в друзьях в левой панели с точкой статуса.
- [ ] Встречная заявка (**C** шлёт **A**, когда **A** уже отправил **C**) → сразу дружба.
- [ ] Заявку из списка участников комнаты: клик по имени участника → «Send friend request»; если уже друзья → «Message».
- [ ] DM работает как комната: доставка сразу, reply, edit, delete своего, поиск, «typing…». Удалить чужое сообщение в DM нельзя никому.
- [ ] Decline / Cancel заявки: у другой стороны заявка пропадает.
- [ ] Remove friend → у обоих DM становится только для чтения («You are no longer friends»), в левой панели — в «Past conversations» с 🔒. История видна.
- [ ] Ban user из карточки собеседника: подтверждение с текстом «They won't be able to contact you…» → у **обоих** сразу поле ввода заменено плашкой «One of you has blocked the other». В меню сообщений только «Copy text».
- [ ] После бана **B** не может отправить заявку **A** и пригласить **A** в комнату (сообщение об ошибке). Сообщения друг друга в общей комнате остаются видны.
- [ ] Contacts → Blocked → Unban: дружба не восстановилась, DM всё ещё только для чтения («You are no longer friends»). Новая заявка и принятие → тот же DM снова доступен для записи со старой историей.
- [ ] Статус собеседника в замороженном DM не показывается.

## 6. Интерфейс в целом

- [ ] Ширина окна < 1280 px: правая панель открывается кнопкой 👥/👤. Ширина < 960 px: левая панель открывается кнопкой ☰.
- [ ] Кнопка « сворачивает левую панель до узкой полосы, » разворачивает.
- [ ] Тёмная тема системы → интерфейс тёмный и читаемый.
- [ ] В консоли браузера (F12) нет красных ошибок, кроме 401 до входа.
